01 • Engineering Context

Project Overview

Understanding the telecommunications operational friction, project goals, targeted users, and strict boundaries.

⚠️

The Problem Explored

Enterprise telecommunications Network Operations Centers (NOCs) suffer from severe operational silos. When an enterprise leased circuit or fiber link fails:

  • Fragmented Records: Customer incident tickets are logged in CRM/helpdesk systems, while field repairs, optical fiber splicing, and router config fixes exist in separate engineering work order dispatch platforms.
  • Manual Correlation Delay: Tier-1 service desk operators must manually search multiple databases to identify which field technician was dispatched, what equipment was replaced, or why an MTU configuration mismatched.
  • LLM Hallucination Risk: Standard generative LLMs fabricate non-existent ticket numbers, hallucinate incident states, and leak private customer identities when answering operational inquiries.
🎯

Project Objectives

Architect an independent, verifiable, end-to-end question answering system that guarantees accuracy, privacy, and speed:

  • Sub-Millisecond Routing: Deterministically classify incoming questions into SQL lookup, semantic search, hybrid correlation, or clarification before touching heavy inference models.
  • 1:M & M:N Graph Traversal: Reliably traverse the relational bridge linking customer trouble tickets to technical engineering work orders.
  • 100% Grounded Synthesis: Constrain answer generation strictly to retrieved evidence with verifiable [SOURCE: type:id] citations.
  • Active Contradiction Critique: Reject conflicting status (OPEN vs RESOLVED), severity, or root cause assertions before user presentation.
  • Identifier Pseudonymization: Deterministically mask corporate client names and operational IDs in client-facing views.
👥

Intended Users

Tailored specifically for mission-critical operations workflows:

  • NOC Tier-1 Service Desk: Instant status lookups for corporate customers (e.g., CP ALL, Apex Logistics) without manual SQL joins.
  • Tier-2 & Tier-3 IP Core / Transmission NOC: Rapid root-cause retrieval for optical fiber degradation, PEA commercial power outages, and BGP route-policy flapping.
  • Service Delivery Managers: High-level customer ticket aggregation, circuit inventory queries, and SLA impact auditing.
🔒

Scope & Safety Boundaries

Strictly bounded as an independent portfolio demo:

  • 100% Synthetic Fictional Data: All companies, circuit references (CKT-88XXXX), ticket IDs (INC-2025-XXXXX), and work orders are deterministically generated. Zero corporate or proprietary company data is used.
  • Zero External Cloud APIs: Runs entirely local. No OpenAI, Anthropic, or external API keys required or contacted.
  • Read-Only Safety: Queries only read from synthetic data stores; no operational modifications or write commands are permitted.
ℹ️

02 • System Design

Technical Architecture & Execution Flow

A nine-stage pipeline guaranteeing deterministic routing, tri-engine retrieval, grounded synthesis, independent claim verification, and safe presentation filtering.

STEP 01

Client Layer

Streamlit web interface (src/ui/app.py) provides free-text input and quick starter prompts. Maintains multi-turn conversation history in st.session_state.

STEP 02

Deterministic Router

Strict 9-level precedence classifier (src/router/classifier.py) extracts regex entities and routes queries in 0.05 ms with zero LLM hallucination.

STEP 03

Tri-Engine Retrieval

Dispatches to parameterized SQLite (exact IDs, bridges, counts), ChromaDB (symptoms, causes), or Hybrid (customer-scoped vector search).

STEP 04

Evidence Context Builder

Formats retrieved records into inert <evidence_context>, neutralizes prompt injection directives, deduplicates chunks, and tags stable [SOURCE: type:id] keys.

STEP 05

Grounded LLM Synthesizer

Dual-mode synthesis: Deterministic Fake Provider (100% offline, ~0.05 ms) or Local Ollama (typhoon2:8b). Strict prompt enforces factual grounding.

STEP 06

Active Guardrail Critic

Extracts factual claims and performs independent contradiction checks against SQLite truth (status, severity, root cause, bridge links). Suppresses false claims on conflict.

STEP 07

Identifier Masking

Deterministic pseudonymization converts INC-2025-00001 to [TICKET-***001] and company names to [CUSTOMER-ALPHA] with zero leakage in user fields.

STEP 08

Safe Presentation Boundary

Strict allowlist gate (PresentationAdapter). Completely blocks internal diagnostic fields, raw database rows, and reverse pseudonym maps from reaching the UI.

STEP 09

Safe Conversational UI

Renders sanitized answer bubble with verified citation chips ([1] [TICKET-***001]), single-query wall-clock latency metric, and safe telemetry expander.

07 • Architecture Trade-Offs

Core Engineering Decisions

Senior-level architectural rationale behind design choices, trade-offs, and failure mode mitigations.

DECISION 01

Coexistence of SQL & Semantic Retrieval

Enterprise NOC data exists on opposite poles of the structured spectrum: tickets and circuits have rigid foreign keys and exact identifiers, whereas technical symptoms and root causes are written in free-form engineer shorthand.

Architectural Trade-Off: Pure vector search fails on exact ID lookups (poor precision on INC-2025-00042). Pure SQL fails on fuzzy symptoms (e.g. “ไฟเบอร์ขาดขุดถนน”). A tri-engine architecture routes structured queries to parameterized SQL and descriptive queries to ChromaDB.
DECISION 02

Deterministic Routing vs. LLM Router

Instead of placing a heavy LLM at the routing layer, a deterministic rule-precedence classifier using precompiled regular expressions inspects entity syntax and keyword boundaries.

Architectural Trade-Off: An LLM router adds 500–2,000 ms of latency and non-deterministic misrouting. The deterministic classifier operates in 0.05 ms with 100% repeatable decisions, while maintaining an explicit security barrier against SQL injection tokens.
DECISION 03

Inert Evidence Context & Prompt Sanitization

Retrieved database rows and vector documents are wrapped inside an inert <evidence_context> container. Text is sanitized to neutralize prompt injection directives (e.g. “ignore previous instructions”) before reaching synthesis.

Architectural Trade-Off: Treats all database text as untrusted data rather than prompt instructions, preventing adversarial payloads from hijacking the synthesis model.
DECISION 04

Decoupled Guardrail Critic (Separate from Synthesizer)

Self-consistency checks performed by the generating model suffer from confirmation bias. The active guardrail critic (GuardrailCritic) runs as an independent post-generation evaluator.

Architectural Trade-Off: Evaluates factual claims against SQLite ground truth. If the synthesizer claims a ticket is OPEN while records confirm RESOLVED, the critic triggers safe degradation and suppresses the hallucinated text.
DECISION 05

Safe Presentation Adapter (Fail-Closed Boundary)

The web UI does not receive internal pipeline dictionaries or raw database objects. The PresentationAdapter maps internal results strictly to an allowlisted SafePresentationView.

Architectural Trade-Off: Blocks forbidden fields (original_answer, claims, contradictions, reverse pseudonym maps). If is_safe_to_present is False, the UI fails closed and suppresses the answer entirely.
DECISION 06

Offline Deterministic Fake Provider for Hermetic Testing

Unit test suites that rely on external APIs or local LLM execution suffer from latency and non-determinism. A custom DeterministicFakeProvider was built to parse <evidence_context> directly.

Architectural Trade-Off: Enables 150 automated tests to run in ~50 seconds with zero network calls and 100% reproducibility, while keeping Local Ollama available for live human demonstrations.

09 • Transparent Engineering

Limitations & Future Roadmap

Honest assessment of current scope boundaries and planned future enhancements.

⚠️ Known Limitations

1. Regex Masking Entity Boundaries
Regex pseudonymization covers Tickets, Work Orders, Circuits, and Customers. Residual fields (engineer aliases, contact phone numbers, site names, and IP addresses) are not masked by regex; this is mitigated by design by barring raw database rows from UI rendering.
2. Routing Vocabulary Bounds
Unseen technical jargon or misspellings not present in the pattern dictionary route to CLARIFICATION or UNSUPPORTED rather than guessing semantic intent.
3. Single-Turn Retrieval Scope
Multi-turn conversational history is maintained at the UI session state level for presentation, but each query is retrieved independently without multi-step plan decomposition.

🚀 Future Roadmap (Stage 10+)

Stage 10: Optional LangGraph ReAct Agentic Workflow
Add multi-step tool-calling agent capabilities for complex queries requiring sequential query planning (e.g. “Find all tickets on degraded circuits and check if field repairs are dispatched”).
Cross-Encoder Semantic Reranker
Implement a second-stage cross-encoder reranker (e.g. bge-reranker-large) to improve semantic Retrieval Precision@5 from 46.3% on large document batches.
Named Entity Recognition (NER) Privacy Engine
Integrate spaCy or transformers-based NER to detect and redact contact person names and technician aliases dynamically across free-form technician activity notes.
